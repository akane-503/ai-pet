# 轻量交接

Git 管代码事实，HANDOFF.md 只补当前意图、约束和下一步。普通任务不创建 state/、快照、租约或额外日志，不为交接自动 commit、push、stash 或清理工作区。

1. 确认当前工作目录和项目根目录。读取 `git rev-parse HEAD`、`git status --short` 和必要的 `git diff --stat`；没有 Git 就记录相关文件及核验依据。未提交和未跟踪文件也是现场，不能只看提交历史。
2. 优先更新本任务已明确使用的交接文件，否则使用项目根目录 `HANDOFF.md`。共享项目中不要覆盖其他任务：有明确会话名时可用 `HANDOFF-<任务名>.md`。旧文件先查看开头和相关段落，不默认通读；覆盖前备份到 `~/.handoff/backups/`，并在新文件保留备份路径。
3. 写一份当前摘要，通常 40–80 行、约 1500 中文字以内；复杂任务的详细证据链接到已有材料。更新当前状态，不累积历次流水账，只保留仍影响下一步的纠正和决策。建议结构：

   ```markdown
   # HANDOFF — <任务名>
   项目根目录：<绝对路径>
   会话启动目录：<绝对路径>
   来源工具：<工具名>；会话 ID：<已知值或未获取>
   代码锚点：<HEAD 或无 Git>；生成时间：<时间>

   ## 当前任务
   目标、验收标准和关键约束；必要时短引用户原话。
   ## 当前状态
   相关文件、未提交工作、关键决策及仍适用的否决理由。
   [已验证] 命令与结果；[未验证] 项；[推测] 单独标明。
   ## 下一步
   1–3 个可执行步骤，含必要文件或命令。
   ## 上下文入口（按需读取）
   原始对话：<当前会话的准确本地路径/受支持链接，或未获取>
   定位：<会话 ID、任务关键词、相关时间或行号，已知多少写多少>
   相关材料：<规格/issue/证据路径或链接>
   历史备份：<如有>
   ```

4. 上下文入口只保存引用，不复制完整对话、工具输出或全部用户原话。只引用能确认属于当前任务的会话，无法获取时如实说明；不扫描全局会话或用“最新对话”猜来源。路径注明 Windows/WSL，跨设备不保证可访问，不自动上传聊天。敏感信息不进入交接。
5. 将交接文件的 Windows 绝对路径追加一行到 `~/.handoff/latest.txt`（Windows 为 `%USERPROFILE%\.handoff\latest.txt`；WSL 使用对应 Windows 用户目录并用 `wslpath -w` 转换路径）。保留这个桌宠发现接口，目录不存在再新建。最后简短回复交接路径。

用户带的参数作为本轮重点；只列下一步实际需要的技能。只有用户明确选择正式 task-handoff 流程时才调用它，并遵循其授权要求；已有 state/ 不意味着本次必须加载整套历史。
