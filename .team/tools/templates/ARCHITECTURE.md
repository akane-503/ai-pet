## 2. 接口契约

| 契约 | 文件 | 版本 | 提供方 | 消费方 | 兼容策略 |
|---|---|---|---|---|---|
|  | `CONTRACTS/xxx.md` | v1 |  |  | 只增不改 / adapter |

规则：

- 契约拥有者定签名；消费者只改自己一侧。
- 破坏性变更 = 版本 +1 + adapter + 迁移任务，不允许直接改签名。
- 契约变更必须走 CR（structural）。

## 7. 演进原则（最小改动）

1. 先加新文件/新模块，再改公共文件。
2. 接口只增不改；破坏性变更走 v2 + adapter。
3. 单任务写集尽量小；跨模块改动拆成多个任务。
4. 结构变更必须有过渡层、回滚点、ADR。
5. 重排只碰受影响任务，其余分支/租约/状态不动。
