# 决策记录与决策门（DECISIONS）

> 项目：{{PROJECT}} · 更新：{{DATE}}  
> 本文件是**决策门**：执行会话遇到全局/破坏性操作时，先写到这里等 Manager，**不要**直接问用户选项。

## 硬规则

- **唯一决策者**：Manager（当前「接管项目管理」的会话；没有 Manager 时由顶层会话兼任）。
- 用户只定**范围/预算**；Manager 在确实无法判定时再升级用户；禁止执行者绕过 Manager 直接抛选项。
- 决策必须落在本文件：背景、选项、建议、影响、决定、决策者、时间。

## 必须过决策门的动作

1. 安装 / 卸载 / 静默安装 / 写注册表 / 改系统设置。
2. `taskkill`、关闭用户正在用的 AI 客户端/宿主进程、杀本机会话。
3. 删除/覆盖用户数据、配置、凭证；删除远程分支。
4. `git reset --hard`、`push --force`、改写已推送历史。
5. 结构性契约/架构变更；大批改保护文件（package.json、lockfile、schema、入口注册）。
6. 任何可能影响用户正在使用的实机的操作。

## 执行者流程

1. **停手**；不要继续，也不要直接 `ask_user_question` 给用户选项。
2. 在本文件追加一条待决：背景、选项、建议、影响、需要谁批。
3. 等 Manager 写明「决定」后再按决定执行；没有决定就保持 `等人`。
4. 待决已有写好的默认/授权时，才可按该默认选项。

## Manager 流程

1. 读本文件 + `node .team/tools/team.mjs status` / `doctor`；可选读 `.team/local/manager-notify.md`。
2. 能判则判并写「决定 / 理由 / 决策者 / 时间」；不能判 → 整理选项升级用户。
3. 相关任务继续 / `reject` / `reopen`；处理完后可 `managerd drain`。
