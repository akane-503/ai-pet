# 项目章程（CHARTER）

> 项目：ai-pet · 建立：2026-11-03 · 产品签收：2026-11-05  
> 这份文件回答「为什么做、做到什么算成、明确不做什么」。**只描述桌宠产品**；通用项目管理控制面不在本仓愿景内。

## 1. 一句话目标

在 Windows 上提供一只常驻桌面的 AI 桌宠：汇总多 AI 工具额度与会话状态，支持角色切换、会话转接（handoff/takeover）与可安装发行版。

## 2. 用户与场景

| 用户 | 场景 | 现在怎么做 | 痛点 |
|---|---|---|---|
| 本机重度 AI 用户 | 同时用 Cursor / Codex / Claude 等 | 各客户端里分别看额度与会话 | 切换成本高，额度/会话分散 |
| 同上 | 想把当前上下文转到另一工具继续聊 | 手工复制粘贴 | 易丢上下文、步骤长 |
| 同上 | 安装/更新桌宠 | 手动解压或旧安装器 | 需要静默安装、卸载、自动更新等产品化能力 |

## 3. 输入 / 输出

- 输入：各 AI 工具本机配置/凭证路径、用户设置、会话导出或转接载荷。
- 输出：Electron 桌宠 UI、额度/状态展示、转接提示与流程、安装包与更新产物。
- 边界：本机单用户；不声称云端多租户协作。

## 4. 非目标（明确不做）

1. **不做通用项目管理 / 多 Agent 写仓控制面**（那是独立仓 `project-team-pm` 的职责）。
2. 不做跨机器分布式锁、团队云端看板。
3. 不替代各 AI IDE 本身的编辑/Agent 能力。
4. 不以「额度 UI / provider 细节」绑架控制面 PROTOCOL。

## 5. 约束

- 技术：Electron + Node；主进程入口热点 `src/main/main.js`（并行改动需谨慎拆分）。
- 环境：Windows；产品真相分支 **`team/integration`**（及 `product/*` 工作树）；**`main` WIP 不当基线**（见 D-002 / 分支 `wip/main-20261105`）。
- 门禁：`npm test`；任务工作树经 `linkDirs` 共享 `node_modules`，禁止在任务树内擅自装依赖。
- 破坏性操作（安装验证杀进程、写注册表等）必须过 `.team/DECISIONS.md`。
